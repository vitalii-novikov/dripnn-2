# План: Гардероб 3×3 (Google Sheets + Form)

> **Статус (2026-09-27): реализовано.** По решению владельца код переписан в
> три файла `CODE_Apps_Script/` на чистом JS — без TypeScript, сборки, npm и тестов; стейджи
> ниже описывают исходный путь и сохранены как история решений. Отличия от плана:
> тиры S–E, поле `Size`, тир из формы как начальный, английские названия вопросов,
> переименование обновляет список «Блок» в форме.

Заменяет идею «фото пола».

## Продукт

- Главный экран: сводка (всего вещей, полоса тиров, без тира) + сетка 3×3 из
  9 блоков. Плитка: обложка (одно фото), название, число вещей, мини-полоса тиров.
- Экран блока: сводка блока (число, полоса тиров) + кнопка «Добавить» (открывает
  форму) + сетка фото 2 колонки. Тап по вещи → нижняя шторка: крупное фото,
  S A B C D, «Без тира», «Удалить».
- Переименование: одна шторка с 9 полями (кнопка на главном).
- Добавление вещи — только через Google Form с обязательным фото.
- Удаление: вещь скрывается в служебном листе, фото — в корзину Drive.
  Лист ответов формы не редактируется никогда.
- Фото: скрипт открывает файл «всем по ссылке», клиент грузит
  `https://drive.google.com/thumbnail?id=<id>&sz=w400` напрямую.
- Только приватное приложение: один проект, *Выполнять как: я*, *Доступ: только я*.

Вне объёма: публичная страница, история тиров, загрузка фото из приложения,
кеширование, триггеры, синхронизация формы из приложения, быстрый рейтер,
отдельный экран статистики.

## Задача для владельца (до стейджа 3)

Создать форму руками и привязать к существующей таблице «Wardrobe»
(та, к которой уже привязан скрипт):

| Вопрос | Тип | Обязательный |
|---|---|---|
| `Блок` | Раскрывающийся список: 9 названий блоков | да |
| `Название` | Текст (строка) | нет |
| `Фото` | Загрузка файла: 1 файл, только изображения | да |

«Ответы → Связать с Таблицами → Выбрать существующую» → «Wardrobe».
Ссылки присылать не нужно: `setup` находит привязанную форму через
`ss.getFormUrl()`, берёт из неё ссылку, `entry.<id>` для предзаполнения блока и
начальные 9 названий блоков (варианты списка «Блок»). Переименование в
приложении обновляет варианты в форме (best-effort; старые имена — aliases).
Старые листы (zones, items, tier_events и т.п.) из прошлой версии можно удалить
вручную — скрипт их не трогает.

## Данные (Google Sheets)

- **Лист ответов формы** — только чтение. Находится по заголовкам `Блок` и
  `Фото` (заголовки ищутся при каждом чтении, порядок колонок не важен).
- **`Blocks`**: `slot (1–9) | name | aliases` — aliases = старые имена через `\n`.
- **`State`**: `itemId | tier | deleted | updatedAt` — строка появляется, когда
  вещь впервые обработана (фото расшарено) или ей поставили тир/удалили.
- **Script Properties**: `SPREADSHEET_ID` (уже есть), `FORM_URL`,
  `FORM_BLOCK_ENTRY` (опц.).

Правила:
- `itemId` = Drive ID фото (из URL в ячейке `Фото`); номер строки не используется.
- Блок вещи = слот, чьё текущее имя или alias совпадает со значением `Блок`
  (trim + регистр). Нет совпадения → вещь в «Без блока» (счётчик на главном).
- Переименование: старое имя уходит в aliases слота; дубли имён/aliases между
  слотами запрещены. Приложение показывает подсказку «обнови список в форме».
- Строка без ID фото пропускается и считается в «ошибки строк».

## RPC (4 функции + setup)

| Функция | Что делает |
|---|---|
| `setup()` (из редактора) | создаёт `Blocks`/`State`, проверяет лист ответов, запоминает ID, расшаривает все фото без строки в `State` |
| `getData()` | 3 bulk-чтения → `{ blocks, items, formUrl, warnings }`; расшаривает до 20 новых фото за вызов и пишет им строку `State` |
| `setTier(itemId, tier\|null)` | абсолютное присваивание, идемпотентно |
| `deleteItem(itemId)` | `deleted=true` под lock, затем `setTrashed(true)` вне lock; идемпотентно |
| `renameBlocks(names[9])` | валидирует, пишет имена + aliases под lock |

Статистика считается на клиенте из `items` (чистая функция, тестируется).
Запись — `LockService.getScriptLock()` только вокруг чтения-слияния-записи `State`/`Blocks`.

## Клиент

- RPC-обёртка с таймаутом 15 с; при таймауте/ошибке — экран с «Повторить» и
  подсказкой «открой в профиле браузера только с аккаунтом-владельцем».
- Скелетон вместо «Загрузка…». Данные загружаются один раз; переход между
  экранами без запросов. Повторная загрузка на `visibilitychange` (возврат из формы).
- Оптимистичные тир и удаление; удаление — тост «Удалено · Отменить» 6 с, RPC
  уходит после истечения; при ошибке RPC — откат и тост.
- «Добавить»: `window.open(formUrl + prefill блока)` синхронно в обработчике клика.
- Дизайн: токены цвета, светлая/тёмная тема, системный шрифт, плитки 1:1 с фото
  `object-fit: cover`, тир-цвета с контрастом ≥4.5:1 (S — тёмный текст),
  тач-цели ≥44px, input 16px (без автозума Safari), `loading="lazy"`,
  `100dvh`/safe-area. Без внешних CDN, всё инлайн.
- Роуты: `#/` и `#/block/<slot>`.

## Риски

| Риск | Смягчение |
|---|---|
| RPC не доходит (несколько аккаунтов в браузере) | Таймаут + экран ошибки с подсказкой; открывать в профиле с одним аккаунтом |
| Workspace запрещает ссылки «всем» | `setup` пробует расшарить и падает с понятной ошибкой; `getData` отдаёт warning |
| Thumbnail-URL Drive требует resource key / меняется | Проверка на реальном деплое в гейте 5; fallback-плашка при ошибке картинки |
| Вопрос формы переименован → колонка не найдена | `getData` возвращает понятную ошибку «нет колонки Блок/Фото» |
| Переименовали блок, форма не обновлена | Aliases сохраняют старые ответы; подсказка обновить список в форме |
| Удаление: Sheet записан, Drive упал | Вещь всё равно скрыта; warning «фото не удалено» |
| Любой со ссылкой на файл видит фото | Выбор владельца; зафиксировано в decisions |
