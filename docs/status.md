# Где мы и что дальше

Обновлено 2026-09-26. План: `.claude/PRPs/plans/floor-map-wardrobe.plan.md`.

## Закрыто

**Этап 0** — контракт проекта: Next 16, TS strict, Vitest с порогом 80%,
Playwright (chromium + mobile WebKit), pgTAP, CI-конвейер.
**Этап 1** — схема, RLS, граница Storage. Владение через составные FK,
append-only `tier_events` на грантах, приватный бакет.

Обе части доказаны прогоном, не на словах: `npm run verify` возвращает 0.

## Готово по коду, гейт открыт

**Этап 2** — auth и границы сервер/клиент. Клиенты, `proxy.ts`, защищённый
layout, вход по magic link, коллбэк, отображение ошибок.

Автотесты закрыты: 49 unit (97.9%), 33 pgTAP, 20 integration, 16 e2e.

**Незакрытая ручная часть гейта:** magic link не проверен на проде Vercel с
телефона — деплоя нет. Это единственное, что отделяет Этап 2 от закрытия.

## Следующий шаг

1. Задеплоить на Vercel, прописать переменные из `.env.example`.
2. В Supabase-проекте добавить прод-домен в `additional_redirect_urls` **с
   шаблоном** `https://<домен>/**`. Без шаблона GoTrue срежет путь — вход
   сломается ровно так, как описано в D15.
3. Пройти вход с телефона. Работает — Этап 2 закрыт.
4. Дальше **Этап 3 — 🚦 гейт: 20 фото на личном iPhone.** До него редактор
   карты не начинается. Код гейта (`/capture/spike` с боевой компрессией и
   очередью) ещё не написан.

## Чего не делать

- Не начинать Этап 7 (редактор карты) до прохождения гейта Этапа 3.
- Не закрывать гейты, требующие телефона или прода, за владельца.
- Не ставить зависимости через `npm install` — только `npm ci`.

## Параллельная ветка идеи

Владелец рассматривает вариант на бесплатных сервисах Google: данные и фото в
Google Sheets, приложение поверх них, ввод вещей через Google Forms в соседнем
окне. Это **отдельное планирование от того же PRD**, а не продолжение этого
плана. Текущая реализация на Next + Supabase сохраняется как есть.
